# IPTV Guardian · 方案 A（GitHub Actions 零运维）

一条**永远不变**的 M3U 订阅地址，后台自动检测失效频道、按评分换到最优源，并持续把频道升级到加载更快、更稳的地址。

## 订阅地址

```
https://liang272.github.io/iptv-guardian/live.m3u
```

播放器只需填一次，地址永远不变。同一仓库下还有两个固定地址：

| 地址 | 内容 |
|---|---|
| `live.m3u` | **通用兼容版**：全部频道；确认失效的排到末尾并标记「待修复·xx」 |
| `healthy.m3u` | **纯净版**：只保留未确认失效的频道，推荐优先用这个 |
| `vlc.m3u` | **仅 VLC / Kodi**：带断流重连、缓冲优化、UA/Referer 透传的增强版 |
| `status.json` | 巡检统计、候选池与加载质量概览、换源日志 |

内容由后台自动更新，但 URL 都不变。

> `live.m3u` / `healthy.m3u` 已改为**最大兼容 M3U 格式**：频道信息行（`#EXTINF`）的下一行直接是播放地址，
> 中间不插入任何 `#EXTVLCOPT`。绝大多数直播软件、电视盒子、IPTV 播放器都按这条规则解析。
> 只有 VLC / Kodi 需要额外优化属性时，才用 `vlc.m3u`。

## 播放软件显示「处理失败 / 解析失败」怎么办

按可能性从高到低排查：

| 可能原因 | 现象 | 处理 |
|---|---|---|
| **① 国内访问不到 `github.io`** | 手机浏览器打开地址也转圈/打不开；软件报「网络错误 / 获取失败」 | 改用下面的**国内加速地址**；或给 Pages 绑已备案的自定义域名 |
| **② 旧版列表的 `#EXTVLCOPT` 导致解析失败**（已修复） | 之前版本能读、某些软件一直报「处理失败」 | 已改为通用兼容格式，**无需换地址**，在软件里删除并重新添加一次订阅（清掉本地缓存）即可 |
| **③ 填错了输入框** | 软件把整条 M3U 地址当成「单条直播源」 | 找「添加订阅 / 网络导入 / M3U 地址 / 播放列表 URL」入口，不是「添加单个频道」 |
| **④ 软件缓存了旧列表** | 服务端已修好，软件仍报错 | 删除订阅后重新添加，或清软件缓存 / 重启 App |
| **⑤ 地址被截断或带多余参数** | 复制时少了 `.m3u`、多了空格或 `?v=` 参数 | 用纯地址，不要带参数 |

**快速自检**：用手机或电脑浏览器直接打开订阅地址。能看到以 `#EXTM3U` 开头的纯文本，说明服务端正常、问题在软件或网络；打不开就是网络层（第 ① 条）。

> M3U 列表只有几十 KB、仅在打开时拉取一次，它决定「能不能读到频道列表」；
> **频道起播快慢取决于流媒体源本身**，换托管地址并不能给频道加速。

## 关于「全自动从全网搜集源」（请先读）

**本项目不做、也不会加入「自动爬取全网／微信／论坛源」的功能。** 原因有两条，都是硬性的：

1. **合规**：这类第三方转播源绝大多数未经版权方授权。规模化抓取 + 自动保活 + 保证可播，等于搭建盗播聚合与分发；微信等封闭生态也没有合法的公开抓取接口，爬取还违反其服务条款。工具只维护地址列表，不提供、不托管、不缓存任何节目内容。
2. **技术现实**：这类源没有稳定的公开目录、普遍带防盗链、存活时间以小时计，海外探测节点又连不上国内内网源。靠爬虫堆数量只会得到一大堆「看起来有、实际播不了」的地址，反而让选源变慢、误判变多。

所以「候选池尽量多」通过**合法、可控**的方式实现：接任意多个**你有权使用的**上游，并且让每个频道的候选都经过真实播放链路验证、按质量排序。下面是具体做法。

## 候选池怎么扩到最多

| 途径 | 做法 | 效果 |
|---|---|---|
| **多个上游** | `sources.json` 里加任意多条，支持 `enabled` / `weight` / `merge_only` | 每个频道自动汇集多个地址 |
| **批量丢文件** | 把 `.m3u` / `.txt` 放进 `sources.d/`，自动扫描并入，无需改配置 | 最省事，见 `sources.d/说明.md` |
| **画质变体归并** | `CCTV1.cn@HD` / `@SD` / `@4K` 自动合并为同一频道的不同候选 | 同一上游也能贡献多个地址 |
| **大型列表只补候选** | `merge_only: true` 的上游只补备用地址、不新增频道 | 接大列表也不会让频道数失控 |
| **自定义补充源** | `custom.m3u` 按频道追加地址 | 针对单个频道（如 TVB 翡翠台）补源 |

上游越多、每个频道的候选越多，换源时可选的最优地址就越多。当前默认已接入 iptv-org 的
5 个地区/语言列表 + 全量 `index.m3u`（仅补候选）+ `custom.m3u`。

> 实测提醒：默认公开上游里 238 个频道大部分仍只有 1 个地址，这是换源率上不去的唯一原因。
> 真正把候选池做厚，请把你自己订阅的多个合法源放进 `sources.d/`，或把方案 B 的聚合结果作为上游。
> 单靠公开列表做不到「每个频道都有多个可换的源」。

## 换源怎么换到最优

不是「随便挑一个能连上的」，而是**多维评分选最高分**：

| 维度 | 作用 |
|---|---|
| 加载延迟 / 首字节 / 首分片耗时 | 越快分越高，直接对应起播速度 |
| 画质（RESOLUTION / BANDWIDTH / URL 标记） | 1080p 优先于 480p |
| 历史成功率、连续失败次数 | 老挂的源自动降权 |
| 最近成功时间、不确定次数 | 长期没验证过的源降权 |
| 上游 `weight` | 你更信任的自有源可加权 |

流程：失效 → 并发探测备用池 → 按评分排序 → **对选中的地址即时复验一次**（拉播放列表 + 拉首分片 + 读数据）→ 通过才切换，不通过就试次优 → 全部不可用则尝试回滚到上一个已验证可用的地址 → 仍不行才标记「待修复」。

「假活」源（播放列表返回 200、但分片 404）会被真实链路验证拦下，不会被选中。

## 加载速度优化

- **探测侧**：24 并发、按 URL 去重、5 秒分级超时、只拉前 32KB 播放列表和首分片前 512 字节；候选池只在换源/抽样时探测，不拖慢常规巡检。
- **持续择优**：空闲时每轮轮转抽样 24 个健康频道，若备用池里有评分明显更高（默认高 20 分）的源，就主动升级过去，单轮最多 8 个。也就是说不只是「坏了才换」，而是逐步把频道切到最快最稳的源。
- **播放器侧（仅 `vlc.m3u`）**：增强版为每条频道写入 `#EXTVLCOPT:http-reconnect=true`（断流自动重连）、`#EXTVLCOPT:network-caching=1000`（缩短起播缓冲），并透传源所需的 `User-Agent` / `Referer`。
  **通用列表 `live.m3u` / `healthy.m3u` 不带这些属性** —— 大量直播软件会把中间的属性行误当成频道地址，导致整份列表「处理失败」，兼容优先。
- **列表体积**：兼容版去掉境外图床的 `tvg-logo` 与数百行属性，文件更小、打开更快。

`status.json` 新增 `candidates_total` / `multi_candidate_channels` / `avg_candidates` / `median_latency_ms` / `optimized` / `rollback` 等字段，可直观看到候选池厚度和加载质量变化。

## 检测周期（已选最短）

| 项 | 值 |
|---|---|
| 调度 cron | `*/5 * * * *` —— GitHub Actions 允许的**最短间隔：5 分钟** |
| 复检范围 | 每轮**全量复检**所有频道（`STALE_SECONDS=0`） |
| 实际间隔 | 5~15 分钟；高峰期 GitHub 可能排队或跳过某次调度 |
| 单次任务上限 | 8 分钟，超过会自动取消（防止排队堆积） |
| 提交策略 | 幂等：无失效/无新增时不写文件、不产生 commit；统计与看板每 30 分钟一次心跳 |

GitHub 不支持低于 5 分钟的定时调度，也没有「秒级」方案。想做到「观看中源挂掉几秒内切换」，只能用方案 B（自建服务 + 播放时代理）。

## 探测结果的地域差异（必读）

检测在 GitHub Actions 的**海外节点**执行，而你在国内观看。很多国内运营商内网源
（如 `39.134.x.x`、`dbiptv.*.chinamobile.com`）海外根本连不上，但国内可以正常播放。因此探测结果分三态：

| 结果 | 判定 | 处理 |
|---|---|---|
| 可用（播放列表有效 + 首分片有数据） | 健康 | 正常输出，参与评分择优 |
| HTTP 4xx/5xx、返回的不是播放列表、分片报错 | 确认失效 | 从备用池按评分单独换源；无备用则移到列表末尾并标记「待修复」 |
| 连接超时 / 拒绝 / DNS 失败 | **不确定**（`unknown`） | **保留原地址、不判失效、不删除频道** |

`status.json` 的 `unknown` 字段就是这类频道的数量。它们仍会出现在两个 M3U 里——宁可保留可能可用的源，也不因为海外探测不到就误删。换源时「不确定」的地址会降权但**仍可作为备选**，避免把国内可用的源排除掉。

**没有任何系统能 100% 保证每个频道每次都播得出来**：源会随时失效、有地域限制和防盗链、跨平台播放器兼容性也不同。本项目做的是把可用率尽量推高：真实链路验证、评分择优、换后复验、失败回滚、持续巡检自愈。

## 为什么周期与仓库可见性有关（重要）

| 仓库可见性 | GitHub Pages | Actions 分钟 | 5 分钟周期 |
|---|---|---|---|
| **Public**（Free 账户） | ✅ 可用 | ✅ 免费不限量 | ✅ 可持续 |
| Private（Free 账户） | ❌ 不支持 | 2000 分钟/月 | ❌ 约 7 天耗尽 |
| Private（Pro/Team） | ✅ 站点仍公开 | 3000 分钟/月 | ❌ 约 10 天耗尽 |

5 分钟一次约 8640 次/月，即使每次只按 1 分钟计费也远超私有仓库免费额度。因此**要用最短周期，仓库必须设为 Public**（这也正是脚本默认部署方式）。仓库里只有公开上游 URL、生成的播放列表和状态日志，不含任何凭据或私密数据。

如果必须保持私有，请同时改两处：

```yaml
- cron: '*/30 * * * *'      # 改回 30 分钟
  env:
    STALE_SECONDS: '1800'   # 与周期一致
```

并把仓库可见性改为 Private；但 Free 账户下 Pages 会失效，订阅地址将无法访问。

## 全中文台名与 TVB 翡翠台

所有频道统一使用**中文台名**（`tvg-name` 和显示名都是中文）。映射表是 `names_zh.json`，
按频道 tvg-id 索引，当前覆盖全部 238 个频道。想改名，直接改该文件里对应的值即可；
以后新增的频道若未收录，脚本会用兜底规则自动生成中文名，不会再出现纯英文台名。
改动映射表会自动触发播放列表重写（有映射表指纹机制，不会被幂等逻辑吞掉）。

**TVB 翡翠台**：iptv-org 里原本叫 `Jade`（tvg-id `Jade.hk`），现已明确命名为「**TVB 翡翠台**」，
归在「中国香港」分组。它在 iptv-org 的地址当前返回 404，因此额外加了可编辑的 `custom.m3u`
补充源；主地址失效时脚本会**只针对这个频道**按评分自动切换过去。

## 文件结构

```
.github/workflows/playlist.yml     定时任务（5 分钟）
.github/scripts/update_playlist.py 检测 / 评分选源 / 换源 / 生成（仅标准库）
sources.json                       上游源清单（weight / enabled / merge_only）
sources.d/                         自定义源批量入口（丢文件即生效）
sources.d/说明.md                  格式与合规说明
names_zh.json                      全量中文台名映射（可编辑）
custom.m3u                         TVB 翡翠台等自定义补充源（可编辑）
state.json                         每频道当前地址、备用池与质量统计（由脚本维护）
docs/live.m3u                      固定订阅文件 · 通用兼容格式（由脚本生成）
docs/healthy.m3u                   纯净版订阅文件 · 通用兼容格式（由脚本生成）
docs/vlc.m3u                       VLC/Kodi 增强版（由脚本生成，含 #EXTVLCOPT）
docs/status.json                   巡检状态看板（由脚本生成）
```

## 日常操作

- **立即检测一次**：`Actions → 自动维护 IPTV 播放列表 → Run workflow`
- **加源（最省事）**：把 `.m3u` / `.txt` 放进 `sources.d/`，push 即自动并入
- **加源（单条）**：编辑 `sources.json` 追加一条
  ```json
  {"name": "自有授权源", "group": "大陆", "weight": 7, "enabled": true,
   "url": "https://your-domain/authorized.m3u"}
  ```
  支持标准 M3U 与 `频道名,URL` 的 TXT。**建议配 ≥2 个上游**，否则很多频道没有备用地址可换。
- **改周期**：改 `playlist.yml` 的 cron（GitHub 最短 5 分钟）
- **调评分/择优**：`playlist.yml` 的 `OPTIMIZE_*`、`MAX_POOL_PROBE`、`NETWORK_CACHING`
- **看换源记录**：`docs/status.json` 的 `log` 字段，或仓库 commit 历史

## 注意事项

- Pages 站点本身是**公开可访问**的（即使仓库私有也是如此）。请不要公开分享订阅地址。
- GitHub Actions 定时任务在仓库 **60 天无任何活动**时会被自动禁用；本方案每 30 分钟有一次状态心跳提交，可避免触发。
- 上游探测频率较高，若某个上游开始限流，把该源 `enabled` 设为 `false` 或移除即可。
- `github.io` 在国内访问可能不稳定。取不到列表请改用上面「国内可访问的加速地址」，或给 Pages 绑定自定义域名 + 国内 CDN，或用方案 B 本机服务。
- 本工具不提供、不托管、不缓存任何节目内容，仅维护地址列表。请只接入已获合法授权或版权方主动公开的直播源，用于个人学习与家庭自建，遵守所在地广播电视与网络视听相关规定；中国香港、中国澳门、中国台湾地区频道的接收传播另有监管要求。
